# antislop audit 001: DevView UI (2026-11-06)

- **Mode:** AFTER.
- **Design direction (R-37):** Hybrid. DevView takes colours and typography from the host `MaterialTheme`, and owns layout, density and component patterns across all modules.
- **Evidence:** the sample app on an Android device (1440×3120) in light and dark mode (dark via the FeatureFlip "Dark Mode" flag), plus the source.
- **Not verified:** iOS, tablet or landscape layouts, TalkBack, and large font scales. Contrast ratios are estimates, not measurements.
- **Priority:** follows the rule tier: H = Hard Gate, M = Purpose-Gate, L = Quality Lock. Logic bugs cite C-2 or C-4 and are rated by impact.
- **Effort:** S = under half a day, M = 1–2 days, L = several days.

## Decisions taken (2026-11-06)

| Topic | Decision |
|-------|----------|
| Scope | All 50 findings are fixed or explicitly decided. |
| NetworkMock operation UI (#21, #22, #24–#29) | A wrap-content bottom sheet for quick picks, with the current state in the header. Network, responses and failures share one radio list. Preview, Compare and Sequence move to a full-screen Navigation3 destination. |
| Top bar (#1–#3) | Each destination renders its own top bar inside its NavDisplay entry, with a back/close navigation icon. `ModuleDestinationAction` gets a required `label` (public API change). |
| Shared UI kit (#9, #12, #14, #16) | A public, documented API in the core `devview` module. |
| Filter pattern (#12, #13, #44) | A search field pinned at the bottom, with a filter toggle that shows a count of active filters. The collapsible panel holds the chip groups and a Clear action. |
| FeatureFlip control (#33–#35) | M3 `SingleChoiceSegmentedButtonRow` labelled "Remote · Off · On", showing the current remote value as supporting text. The 463-line fork is deleted. |
| Watermark (#7) | Kept, with the dark alpha reduced from 0.38 to about 0.07. Reason: the chameleon is DevView's brand mark and tells the developer they are inside the dev overlay, not the host app. |
| Section colours (#11) | Derived from host theme roles instead of hardcoded hex values. |
| Local/Remote badge (#36) | Removed. |
| Analytics event detail (#39) | `AnalyticsLog` gets an optional params map, plus a detail page with copy. |

## Already good (keep)

- **TimeCapsule** is the most polished module:
  - The timeline rail follows the content height.
  - Changes show as `key: old → new`.
  - The list is keyed and animated.
  - It has a real empty state.
- **NetworkMock list:**
  - Method badges use theme roles.
  - Mocked rows get a status rail.
  - There are loading and error states.
  - Each spec has its own tab.
- **Status palettes:** `MockColorScheme` and `LogColorScheme` are deliberately independent of the brand, so success and error read the same in any host theme. Only the dark tones need tuning (#20, #42).
- **Home:** grouped cards with position-aware corners and a clear section rhythm.
- **Clear actions:** Analytics, Console and TimeCapsule ask for confirmation.
- **FeatureTriStateSwitch semantics:** `selectableGroup` with `Role.RadioButton` is correct. The control is replaced anyway (#35), and the new one must keep equivalent semantics.

## Findings

### Core shell (`devview/src/commonMain/kotlin/com/worldline/devview/`)

1. **H · R-39 · M**: Top-bar action icons render with `contentDescription = null` (`DevView.kt` ~300), and `ModuleDestinationAction` has no label field. Refresh, Sort, Restore and Delete are unnamed for TalkBack and visually ambiguous. NetworkMock's history-style "Restore" icon means "reset all to network".
2. **H · C-2 · S–M**: The top bar has no back or close icon, so navigation relies on system back. That leaves no visible exit on iOS (not verified).
3. **H · C-2 · L**: The title and actions switch as soon as the backstack changes, while NavDisplay is still animating the old content. Seen on device: "Analytics" with the trash icon over Home, and "DevView" over Analytics on back. Cause: one shared Scaffold/TopAppBar derived from `backstack.last()`.
4. **M · R-04 · S**: Analytics and TimeCapsule both fall back to the LOGGING default icon (`FormatListNumbered`), so one group shows two identical tiles.
5. **L · R-20 · S**: Names differ between home and screen: "FeatureFlip" vs "Feature Flip", "TimeCapsule" vs "Time Capsule", "NetworkMock" vs "Network Mock".
6. **L · C-3 · S**: `Module.subtitle` exists, but no built-in module sets it, so the three Logging modules are hard to tell apart.
7. **M · R-07 · S**: The full-screen chameleon watermark (`HomeScreen.kt`, alpha 0.07 light / 0.38 dark) has no written purpose. At 0.38 in dark mode it competes with the cards.
8. **L · R-06 · S**: Section headers are raw uppercase enum names (`section.name.replace('_',' ')`). The NetworkMock sheet repeats the same style ("NO MOCK", "SUCCESSFUL MOCKS").
9. **L · R-11 · M**: The grouped-list pattern is implemented three times with three corner radii: `internal/components/ModuleItem.kt` (`shapes.medium`), the NetworkMock sheet's `groupedCard` (12dp), and TimeCapsule's `CardShape`.
10. **L · API hygiene · S**: `ModulePosition` is a public enum in an `internal` package.
11. **L · R-01 · S**: `core/Section.kt` hardcodes hex tile colours (documented in `docs/guides/theming.md`), which conflicts with the Hybrid direction.

### Cross-module patterns

12. **M · R-05 / C-1 · L**: Four filter UIs do the same job:
    - FeatureFlip: chips and search, always visible.
    - Console: two chip rows and search, always visible.
    - Analytics and NetworkMock: search with a chevron-collapsed panel.
13. **H · C-2 · S**: When the filter panel is collapsed, nothing shows that filters are active. The chevron label is static ("Expand filter" in Analytics, "Expand filters" in NetworkMock), so a filtered list looks like missing data.
14. **M · R-27 · M**: Empty states are inconsistent:
    - Console: plain text in the top-left corner.
    - NetworkMock: plain text with no clear-filters action.
    - Analytics: centred text.
    - FeatureFlip and TimeCapsule: icon plus text.
15. **L · C-4 · S–M**: Search, filter and expanded state are held in plain `remember` in FeatureFlip, Analytics, Console, NetworkMock and TimeCapsule, so configuration changes lose them.
16. **L · R-05 · S**: The "3dp coloured rail + 13dp padding" row is duplicated in `devview-networkmock/.../components/EndpointCard.kt` and `devview-analytics/.../components/AnalyticsLogItem.kt`.

### NetworkMock list (`devview-networkmock/src/commonMain/kotlin/com/worldline/devview/networkmock/`)

17. **M · R-01 / R-29 · S–M**: Every unmocked row shows a saturated blue "Network" chip. The default state is the loudest element, so mocked rows don't stand out. Dark mode is worse: bright blue and green chips with dark text on every row.
18. **H · R-26 · S**: "Reset all to network" (`NetworkMock.kt:141`) is destructive and runs with no confirmation, while Clear in the other modules confirms.
19. **L · C-1 · S**: The sort menu doesn't mark the current sort, and the sort is passed as a label `String` through a `SharedFlow` (`NetworkMock.kt:136-139`).
20. **L · R-21 · S**: The dark `theme/MockColorScheme.kt` uses bright mid-tone containers with dark content (for example successful `0xFF70D976`/`0xFF103C13`), which looks neon on dark surfaces.

### NetworkMock operation sheet

21. **H · C-3 · M–L**: The sheet is fixed at 65% height (`NetworkMockOperationSheet.kt`: `fillMaxHeight(fraction = 0.65f)`, `skipPartiallyExpanded = true`). Short tabs leave about half the sheet empty, while the Preview and Compare code and diff views are cramped.
22. **M · R-24 · M–L**: Preview is a hidden fourth page inside the Responses tab. The tab bar still says "Responses" while the content is swapped in place.
23. **H · R-39 · S**: The selected response is a bare `Icons.Rounded.Check` with `contentDescription = null` (`components/MockItem.kt`). Rows use `.clickable` without `selectable`, `Role.RadioButton` or `stateDescription`, so TalkBack can't tell which response is active.
24. **M · R-39 · S**: The selection check and the preview eye share size and colour, so state and action look alike, and unselected rows show nothing.
25. **M · C-2 · S**: The sheet header doesn't show the operation's current state.
26. **M · R-27 · M**: In Sequence (`SequenceBuilderPage.kt`), "Save Sequence (0)" is disabled with no reason given:
    - The two-step minimum (`steps.size >= 2`) is never stated.
    - STEPS has no empty placeholder.
    - Steps can't be reordered.
    - Step keys are based on index.
27. **L · R-05 · S**: Sequence's "Available responses" are plain rows, while Responses uses grouped cards. Header styles differ as well (32dp indent vs 16dp flush, different colours).
28. **L · R-05 · M**: The Failure tab usually holds two rows (Timeout, Connection refused) on an otherwise empty page.
29. **M · C-1 · S**: With nothing to compare, "Compare with…" is a disabled TextButton that reads like a grey placeholder in both themes (`MockResponsePreviewPage.kt`).
30. **L · C-2 · S**: The JSON preview has no copy action and no `SelectionContainer`.
31. **L · R-31 · S**: The KDoc in `components/MockResponseDiffContent.kt` (~55) says the diff colours map to primary/secondaryContainer. They are hardcoded in `components/MockResponseDiffColors.kt:10-19`, with one palette for both themes (light blocks on a dark surface). The dark diff was not checked on device.
32. **L · cleanup · S**: Leftover code:
    - The `SequenceBuilderPage(showHeader = true)` default is unused (the sheet passes `false`).
    - The sheet's `groupedCard` duplicates the core grouping.

### FeatureFlip (`devview-featureflip/src/commonMain/kotlin/com/worldline/devview/featureflip/`)

33. **H · R-25 / R-34 · S–M**: The selected tri-state segment fails contrast in both themes. Light: navy icon on primary `0xFF602BD4`, about 2.2:1. Dark: light icon on a light lavender fill, about 1.3:1. UI components need at least 3:1.
34. **H · R-39 · M**: The control is icon-only:
    - TalkBack reads raw enum names ("LOCAL_ON", "REMOTE").
    - The selected REMOTE segment is filled red or purple depending on a hidden `defaultRemoteValue`.
35. **M · R-31 · M**: `components/FeatureTriStateSwitch.kt` (463 lines) forks Material SegmentedButton internals, although M3 `SingleChoiceSegmentedButtonRow` exists.
36. **L · R-09 · S**: The "Local"/"Remote" badge under each feature repeats what the control already shows.

### Analytics (`devview-analytics/src/commonMain/kotlin/com/worldline/devview/analytics/`)

37. **H · C-2 · S**: The empty-state copy is wrong (`AnalyticsScreen.kt` ~370). If only category or time filters are active and nothing matches, it says "Analytics logs will appear here", because it only checks `filterQuery.isBlank()`.
38. **H · C-2 · S**: The time-range filter (5m/15m/30m) captures `Clock.System.now()` inside `derivedStateOf`, so the window doesn't move until another input changes.
39. **M · C-2 · S/L**: Events can't be inspected or copied, and `model/AnalyticsLog.kt` `AnalyticsLog(tag, screenClass, timestamp, type)` has no parameters.
40. **L · R-29 · S**: Eleven categories share a few container roles, and each row is colour-coded twice (rail plus chip).
41. **L · R-05 · S**: The stat cards use a two-column grid, which leaves the third card alone on its row.

### Console (`devview-consolelogger/src/commonMain/kotlin/com/worldline/devview/consolelogger/`)

42. **H · R-25 · S**: The light WARNING colour `0xFF837807` (`theme/LogColorScheme.kt`) on the light surface is about 4.3:1 for bodySmall text, under the 4.5:1 minimum.
43. **M · C-3 · M**: Entries form one undifferentiated monospace stream:
    - Multi-line stack traces print in full.
    - Entries aren't separated.
    - Colour is the only level marker.
    - There's no selection or copy.
44. **L · R-29 / R-06 · S**: Seven level chips are always visible, labelled with uppercase enum names, each with its own neon outline. Selected and unselected states are hard to tell apart.
45. **L · C-4 · S**: `itemsIndexed` has no keys on an auto-scrolling, growing list.

### TimeCapsule (`devview-timecapsule/src/commonMain/kotlin/com/worldline/devview/timecapsule/`)

46. **M · C-1 · S**: "Restore" appears on the current (newest) entry (`components/TimeCapsuleRow.kt`). Pressing it changes nothing and records a duplicate entry.
47. **H · R-03 · S**: The expand IconButton is forced to `size(32.dp)`, below the 48dp touch target (to verify: M3's minimum interactive size may still expand the touch area).

### Sample app (secondary)

48. **H · C-2 · S**: `sample/shared/src/commonMain/kotlin/com/worldline/devview/sample/DevViewApp.kt:93-102` logs the sample analytics events in the composable body, so every recomposition logs them again (34 became 68 after toggling Dark Mode).
49. **H · R-34 / R-25 · S**: Status-bar icons stay white on the light theme (`sample/androidApp/.../MainActivity.kt:16`, `enableEdgeToEdge()`). Inferred cause: the bars follow the system theme while the app follows the FeatureFlip "Dark Mode" flag.
50. **L · R-05 · S**: The sample home screen is a stack of equal-weight filled buttons. "Make Ktor call" and "Reset Ktor call" touch, and the docs text is dumped raw.

## Leave as is

- Hues of `MockColorScheme` and `LogColorScheme`: they carry status meaning on purpose. Only the dark tones change (#20, #42).
- The Global Mocking row, the spec tabs and the method badges.
- TimeCapsule's structure. Only #46 and #47 apply.
